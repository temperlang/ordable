# Ordable

Sorts strings in natural order, the way people expect: `file2` before
`file10`, since runs of digits compare as numbers.

## Examples

In Temper, and the same API in each supported language:

```temper
let names = ["img12.png", "img10.png", "img2.png", "img1.png"];
sortNatural(names); // img1.png img2.png img10.png img12.png

compareNatural("file2", "file10"); // Negative: file2 comes first
compareNatural("a", "B"); // Negative: case only breaks ties

// Any items, by a string from each, such as files by name.
sortNaturalByKey(files) { file => file.name };

// A string that sorts naturally by plain comparison, as in a database.
naturalKey("file10"); // Sorts after naturalKey("file2")

// Options: an Order has the same functions as methods.
let sensitive: Order = { caseSensitive: true };
sensitive.sort(names); // Every IMG before every img, as plain sorting does
```

Also: a [tour](demos/README.md) of the whole API in each language, with
identical output, and a [site](site/) to try natural sorting in the
browser, beside plain sorting and `Intl.Collator`.

## Rules

- Runs of decimal digits compare by value, at any length, without
  overflow. Digits in any script count (Unicode 15.0), such as Arabic-Indic
  `٢` or fullwidth `２`, and a run is all from one script.
- Letters compare without their accents or case first, so `é` and `É`
  sort with `e`, and letters fold fully, so `Σ` matches `ς` and `ß`
  matches `ss`. Everything else compares by code point.
- Two strings compare equal only if they're the same, so sorting gives one
  answer whatever the input order. Leading zeros (`1` before `01`), the
  digits' script (`1` before `١`), accents (`e` before `é`), case
  (`a` before `A`), and odd forms (`K` before the Kelvin sign) only break
  ties, in that order.
- Options, in an `Order`: `upperFirst` (`A` before `a` in ties) and
  `caseSensitive` (case counts as much as the letter, so every `B` comes
  before every `a`).
- No locale rules: that's for ICU or the platform.

Ordable's Unicode tables (decimal digits, case folding as 202 compact
runs plus 104 full foldings, 977 accented letters' base letters, and 30
odd forms) are
generated by `uv run scripts/unicode_tables.py`, which checks them
against Python's Unicode data for every code point, pinned to Unicode
15.0.0. They're internal, so Ordable can switch to Unicode support built
into Temper later without changing its API. Natural keys depend on them,
so a release that changes keys (a new Unicode version, say) will say so.

## Roadmap

- **Done:** natural order with numbers of any length, a total order,
  sorting by key, decimal digits in any script, and Unicode case folding.
- **Compared** with the usual tools: see
  [docs/comparisons.md](docs/comparisons.md).
- **Done:** natural sort keys (`naturalKey`), which `sortNatural` uses
  for lists past a few items, and which Python can sort by and databases
  can `ORDER BY`.
- **Done:** accents sort with their base letter (`e`, `é`, `f`), and `ß`
  matches `ss`.
- **Done:** defaults as people expect, with case only breaking ties
  (lowercase first), and an `Order` class for options (`upperFirst`,
  `caseSensitive`).
- **Next:** decomposed text (`e` plus a combining accent sorting as `é`);
  smarter punctuation, checked against real-world samples; and more
  options: signed and decimal numbers, a strength for equality across
  equivalents, and a generic `sortByKey` method on `Order` once Temper's
  C++ backend allows it.
- **A spec:** the source as a readable specification of the default
  order and every option, with its tests beside it, and comparison
  tables so people can choose well.
- **Started:** a [showcase site](site/), where you pick or type lines
  and see natural order beside plain sorting and `Intl.Collator`, with
  the code in every language.
- **Done:** compact natural keys, usually about as long as their string:
  levels after the first only record what's unusual (accents, uppercase,
  leading zeros), so `file10`'s key is 8 code points.
- **Before 1.0:** be sure we love the natural key format, since stored
  keys depend on it.

## Languages

Made in Temper, Ordable supports these languages, and its tests run on each:

- C++
- C\#
- Java
- JavaScript
- Lua
- Python
- Rust

## Development

Written with Claude Code and Opus 5.5.

Run tests with [Temper](https://temperlang.dev/), on one backend while
working:

    temper test -b py

Or on all of them:

    temper test -b cpp -b csharp -b java -b js -b lua -b py -b rust

Run the tour in every language against `temper.out/`, checking each prints
the same text (see [demos](demos/README.md)):

    uv run demos/run.py

Build and preview the site, which uses the JS backend's output:

    temper build -b js
    npm ci --prefix site
    uv run site/build.py
    python3 -m http.server -d site/build

CI runs the tests and the tour on every backend for pull requests and
pushes to `main`, using Temper's nightly `dev` build, and publishes the
site from `main`. Source files in `src/`
are literate Markdown, with tests next to the code they cover.
